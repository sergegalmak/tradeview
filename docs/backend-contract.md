# Контракт backend: MarketSnapshot v2

Это контракт **клиента**, не реализация сервера и не подтверждение готовности
аналитической модели. Предыдущий демонстрационный JSON-контракт несовместим с v2:
нельзя молча заполнить отсутствующие источники или историю вымышленными значениями.

## Транспорт и настройка

- `TRADEVIEW_API_URL`: HTTPS endpoint, `GET`, `Accept: application/json`.
- Возвращается один объект `MarketSnapshot`. Тайм-аут клиента — 15 секунд,
  допустим только статус 2xx, тело не более 10 МБ (проверяется после загрузки).
- Все даты — ISO-8601 с часовым поясом, например `2026-10-23T20:00:00Z`,
  без дробных секунд (`JSONDecoder.DateDecodingStrategy.iso8601`).
- Ключи JSON — camelCase. Числа должны быть конечными, не строками.
- Ошибка конфигурации, HTTP, JSON или валидации не подменяется демо-ответом.
- Поддержка аутентификации, потоковой загрузки, retries/rate limits и пагинации
  требует отдельной серверной и клиентской реализации. Один снимок с историей
  не является масштабируемым API на 100 000 пользователей.

Каноническая структура — Codable-типы в
[Domain.swift](../Sources/TradeviewCore/Domain.swift), транспорт —
[DataSources.swift](../Sources/TradeviewCore/DataSources.swift).

## Верхний уровень

| Поле | Содержимое |
| --- | --- |
| `source` | Конверт качества, версий, актуальности и прав отображения |
| `indices` | `symbol`, `name`, `changePercentage` (0.48 означает +0.48%, не 48%) |
| `stocks` | Бумаги с текущим сигналом и lineage |
| `signalHistory` | Полные снимки ранее выпущенных сигналов, не сокращённые строки |

Пустой `stocks` допустим только при `quality != complete`. Тикеры и символы
индексов должны быть уникальны; тикер — непустой upper-case без крайних пробелов.

### source

Обязательные поля: `name`, `updatedAt`, `modelVersion`, `isOfflineDemo`,
`schemaVersion` (= 2), `featureVersion`, `validUntil`, `quality`, `issues`,
`displayRightsConfirmed`.

- `quality`: `complete`, `degraded` или `unavailable`.
- `issues`: массив сообщений о проблемах; непустой массив блокирует публикацию.
- `updatedAt` не может находиться в будущем. `validUntil` — не раньше `updatedAt`
  и не позже чем через 96 часов. Это верхняя защитная граница EOD-прототипа,
  **не** real-time SLA. Для минутных данных задайте короткий срок на сервере.
- `displayRightsConfirmed` — утверждение доверенного backend о правах; само по
  себе поле не заменяет проверку договора или разрешений на redistribution.
- Демо, деградация, просрочка и неподтверждённые права блокируют активные действия,
  проценты и локальные уведомления. Интерфейс перепроверяет часы каждые 30 секунд.

## Бумага и временная последовательность

`Stock`: `ticker`, `name`, `sector`, `price`, `dailyChangePercentage`,
`marketCapBillions`, необязательный `peRatio`, `priceHistory`, `signal`, `provenance`.
Цена и капитализация положительные; история состоит из уникальных `date` и
положительных `close`, без точек позже `updatedAt`.

`MetricProvenance` содержит:

- `metric`: как минимум `price`, `marketCapBillions`, `peRatio`, `priceHistory`,
  `signal`; повторные идентификаторы метрик недопустимы;
- `eventAt`, `publishedAt`, `receivedAt`;
- `provider`, `sourceID`, `schemaVersion`, `quality`, `limitation`.

Для каждой записи:

`eventAt <= publishedAt <= receivedAt <= dataCutoff <= generatedAt <= updatedAt`.

При `source.quality == complete` каждая запись lineage также должна быть
`complete`. Цена на момент расчёта и сам расчёт не могут быть старше 96 часов
от соответствующего среза. Более строгие лимиты по рынку/сессии/типу данных
должен обеспечивать backend. Наличие метаданных не доказывает отсутствие
look-ahead bias: нужны сохранённые raw-ответы, point-in-time feature store и тесты.

## Сигнал и вероятности

`InvestmentSignal`:

- `action`: стабильный код `buy`, `watch`, `hold`, `reduce`, `avoid`, а не перевод;
- `horizon`: число месяцев **1, 3, 6 или 12**;
- `confidence`: 0…1, внутренний показатель полноты/согласованности; UI показывает
  низкую (<0.60), среднюю (0.60…<0.75) или высокую (>=0.75) уверенность;
  это **не вероятность успеха** и не ML-рейтинг доходности;
- `explicitEvent`: `id`, `title`, `benchmark`, необязательные `probability` и
  `calibration`, `expectedBy`; конец события должен совпадать с UTC-календарной
  датой `generatedAt + horizon` месяцев;
- `scenarios`: три уникальных сценария с `title`, `description`,
  `minimumReturn`, `maximumReturn` (доли, -0.10 = -10%; нижняя граница >= -1);
- `drivers`, `risks`, `invalidationConditions`, `rationale`;
- `generatedAt`, `dataCutoff`, `modelVersion`, `featureVersion`, `featureSnapshotID`.

Модель/версия признаков должны совпадать с конвертом выпуска. Без валидного
`CalibrationEvidence` вероятность не публикуется, даже если backend прислал число.
Свидетельство содержит:

| Поле | Проверка |
| --- | --- |
| `eventID` | Совпадает с `explicitEvent.id` |
| `modelVersion` | Совпадает с сигналом |
| `horizon` | Совпадает с сигналом |
| `sampleCount` | Не меньше 200 |
| `brierScore` | Конечное число в диапазоне 0…1 |
| `evaluatedAt` | Не позже выпуска сигнала |
| `reportID` | Непустой идентификатор сохранённого отчёта |

Это **проверка полноты свидетельства, а не статистический тест калибровки**.
Backend обязан проверить held-out/walk-forward результаты, режимы, классы событий,
reliability diagram, статистическую достаточность и регистрацию версии модели.
Число 200 — консервативный нижний порог клиента, его может оказаться недостаточно.
При недостатке наблюдений возвращайте `probability: null`, `calibration: null`.

## История

`SignalHistoryItem`: `ticker`, полный `signal`, **исходный** `source`, `provenance`.
Нельзя заменять конверт старой записи текущей датой ответа или текущей версией.
Ключ: namespace demo/live + тикер + точный `generatedAt` + `modelVersion`.
Повтор с тем же ключом и тем же содержимым идемпотентен; иное содержимое
отклоняется. Новое обновление рыночного конверта не переписывает дату выпуска
уже сохранённого текущего сигнала. Смена demo/live не удаляет архив.

Клиент сохраняет полученные полные записи в локальных UserDefaults, не удаляя
пропавшие из очередного ответа. Повреждённый архив блокирует обновление вместо
молчаливой перезаписи. Это **не tamper-proof аудит**: пользователь может изменить
или удалить локальное хранилище. В production сервер должен предоставлять
append-only журнал, версии исходных признаков и отдельно аудируемые результаты.
До реализации таких результатов UI показывает «ещё не рассчитан».

## Локальные алерты

Правила в [Alerts.swift](../Sources/TradeviewCore/Alerts.swift) реагируют только на
переходы между двумя свежими, полными, лицензированными снимками с возрастающими
датами. Повтор того же снимка не генерирует новое событие. Истёкшие/демо-данные,
первый запуск и первое восстановление после сбоя не генерируют уведомления.
События проверяются только при обновлении открытого приложения. Доставка e-mail,
web push, фоновые задания и серверные идемпотентные очереди не реализованы.
