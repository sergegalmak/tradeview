# Tradeview

Нативный **macOS-прототип**, а не законченный веб-MVP из исходного ТЗ.
Написан на **SwiftUI / Swift Charts**. Есть Xcode-проект и Swift Package с
независимым Core-слоем и тестами состояния приложения. Торговые поручения,
брокерские права и брокерские секреты не поддерживаются.

## Реализовано

- Обзор рынка с индексами, выбранными сигналами и графиком динамики.
- Скринер по названию/тикеру, сектору, действию, согласованности данных,
  минимальной капитализации и максимальному положительному P/E.
- Карточка идеи с горизонтом **1 / 3 / 6 / 12 месяцев**, явным событием и
  бенчмарком, диапазонами сценариев, драйверами, рисками и условиями отмены.
- Вероятность скрыта без калибровочного отчёта, совпадающего по событию,
  горизонту и версии модели. Демо не содержит вероятностей.
- Локально сохраняемые watchlist и введённый вручную портфель.
- Атомарный импорт портфеля из UTF-8 CSV; повторные лоты агрегируются по тикеру
  при анализе концентрации. Позиции без котировки сохраняются, но итоговый P/L
  не публикуется до получения полной оценки.
- Локальный архив полных исходных сигналов с версиями и источниками. Повторная
  загрузка не удаляет записи; конфликт содержимого с тем же ID отклоняется.
  Открывается именно исторический снимок, а не текущая карточка.
- Локальные правила алертов: новая покупка, смена действия, пересечение цены
  вверх/вниз. Проверяются при успешном обновлении открытого приложения, не в фоне.
  Первичная загрузка, демо, деградация данных и восстановление после ошибки не
  создают ложных уведомлений. Лента ограничена последними 500 событиями.
- Общая блокировка действующих рекомендаций и вероятностей при демо, истечении
  срока актуальности, ошибке загрузки, неполных данных или неподтверждённых правах
  на отображение. Предупреждение видно на всех экранах, даты содержат часовой пояс.

## Данные и безопасность

Без настройки backend используется **синтетический офлайн-набор** с фиксированным
историческим срезом 2026-10-23 20:00 UTC. Это не реальные котировки, модель или
backtest. Сценарии — шаблоны для проверки интерфейса. Обновление демо не
переставляет дату на текущую и не делает данные «свежими».

Для подключения своего backend задайте **TRADEVIEW_API_URL** в Environment
Variables схемы запуска Xcode (для запуска из SwiftPM — в окружении процесса).
Значение — полный HTTPS URL нормализованного снимка, без логина и пароля.
Невалидная настройка или отказ сервера **не переключают приложение на демо**.
При запуске до первого успешного ответа состояние пустое; после ошибки предыдущие
данные остаются доступными только с предупреждением и блокировкой рекомендаций.

`BackendAPIClient` проверяет HTTP-статус, схему, диапазоны значений, уникальность
тикеров, наличие lineage и временной порядок публикации/получения/расчёта.
Срок актуальности задаётся backend в `validUntil` и ограничен сверху 96 часами;
для real-time данных сервер обязан задать существенно меньший срок.

Контракт и ограничения: [docs/backend-contract.md](docs/backend-contract.md).
Ключи поставщиков должны оставаться на сервере. OAuth/OIDC в клиенте пока нет;
не используйте query-параметры URL для передачи секретов. Локальные UserDefaults
не являются шифрованным хранилищем или защищённым серверным аудитом.

### CSV портфеля

Заголовок: `ticker,shares,average_cost`.

```csv
ticker,shares,average_cost
MSFT,12,420.00
GOOGL,16,172.00
MSFT,3,430.50
```

Разделитель — запятая, десятичный знак — точка; поддерживаются BOM, CRLF и
кавычки CSV. Цена может быть нулевой, количество должно быть положительным;
NaN/Infinity запрещены. Лимиты: 1 МБ и 10 000 записей на импорт. Ошибка в любой
строке отменяет весь импорт. Импорт добавляет лоты, не заменяя текущий портфель.

## Запуск и проверка

Требования: macOS 14+, Xcode 15.3+ или Swift 5.10+.

```bash
open Tradeview.xcodeproj
xcodebuild -project Tradeview.xcodeproj -scheme Tradeview -configuration Debug build
xcodebuild -project Tradeview.xcodeproj -scheme Tradeview -configuration Debug test
```

Для проверки модели и источников данных без UI можно использовать:

```bash
swift build --target TradeviewCore
swift test --filter TradeviewCoreTests
swift test
swift build -c release
```

CI проверяет Core, весь клиент, Debug/Release и XCTest на macOS. Нужен выбранный
полный Xcode, а не только Command Line Tools, для SwiftUI/XCTest и Xcode-сборки.

## Что не реализовано и обязательно до production

1. Веб-клиент, backend, аккаунты/RBAC/OIDC, администрирование и серверный аудит.
2. Лицензированные ingestion-воркеры, raw-хранилище, point-in-time данные,
  корпоративные действия, делистинги и мониторинг качества/задержек.
3. Реальный факторный скоринг с версионируемыми весами, ML, walk-forward
  backtest, учёт издержек, калибровочные диаграммы и drift-мониторинг.
  Минимум 200 наблюдений в клиентском шлюзе — **защитный порог, не доказательство
  калибровки**. Клиент доверяет отчёту backend, не пересчитывает его статистику.
4. Фактические результаты исторических сигналов: сейчас явно «ещё не рассчитан».
  Наличие локальных неизменяемых снимков не означает серверную воспроизводимость.
5. E-mail, web push, фоновый планировщик и расширенные событийные алерты.
6. Полный набор фундаментальных/новостных/макро/технических показателей,
  готовые подборки скринера и лицензированные данные позиционирования.
7. Английская локализация и аудит доступности (добавленные подписи не означают
  подтверждённое соответствие WCAG).
8. Подтверждение всех прав на данные и юридическая классификация сервиса.

Сервис не обещает доходность. Прошлые результаты не гарантируют будущие.
